# 工具正文与整组原生文件的共同授权

状态：schema33 服务端实现已通过固定 144 个质量输入的全仓验收：379 项普通测试、6 项单独执行的实际检测器/S3 专项，fmt、Clippy `-D warnings` 和 release 全部通过。最终发布 42 项、工具结果 17 项及 MCP 18 项包含在普通测试中。核心镜像已构建，105 个编译输入与本次源码逐字一致；schema32→33 的真实数据库与 20 用途升级另在验证。固定生产器、capture broker、opaque resolver 与真实身份、原生宿主的组合验收尚未完成，Hermes 附件及 TTS 保持关闭，R1 未退出。

## 不可变的整组来源

登记工具结果时，服务端从原始 input operation、claim、完成 receipt、批次、manifest 和已接收文件推导全部来源。最终助手正文则绑定原轮次的全部批次及每份对应的不可变工具结果。调用方不提交文件列表或摘要，不得挑选部分文件；未封存批次、缺失工具结果、不同 Key 或模型的批次都会阻止登记。

有文件的元数据和治理 payload 增加 `artifact_set`；纯文本仍不增加该字段，原 payload 摘要不改变。

```text
artifact_set = {
  contract: "runtime-artifact-set-v1",
  files: [全部原始文件事实，按 input_operation_id / ordinal 排序],
  sha256: SHA256(规范 files JSON)
}
```

每份文件严格包含九个字段：`asset_id`、`batch_id`、`input_operation_id`、`ordinal`、`sha256`、`byte_length`、`producer_revision`、`manifest_sha256`、`expires_at`。UUID 与摘要小写，数量为整数，时间使用 UTC 六位微秒和 `Z`。拒绝额外字段、重复、重排、替代 UUID 写法和浮点数量；Rust 与 SQL 对同一固定扁平对象计算相同摘要。该集合与单文件审阅的 22 字段 `runtime-artifact-mp4-v1` 是两个合同。

每个批次最多 8 个文件、64 MiB；最终轮次最多 64 个文件。超过上限明确拒绝，不截断。结果期限固定为配置期限、原批次、文件和轮次期限的最小值；原来源不足 60 秒时可使用剩余正期限，重放不会续期。

数据库 INSERT 触发器独立校验完整集合和来源期限；使用 tenant 元组写入 fence 序列化 API 与直接 SQL 写入。并发 RC 写入不能遗漏来源，旧 RR 快照发生冲突时拒绝。工具结果封存后不能给其追加批次；最终正文封存后不能追加批次、工具结果或授权新工具输入。原已完成回执仍可恢复，未派发的 MCP 调用收到已知拒绝并保留 `not_submitted` 审计。

## 释放顺序与最后一次授权

```text
原工具正文：全部原文件授权 → 当前工具输出策略 → 正文与全部文件再次授权
最终正文：整轮全部文件授权 → 每份原工具输出策略 → 当前 post 策略 → 所有授权再次核对
```

先完成整轮文件检查才允许原工具的模型检测。单批次获准不能提前触发另一份最终发布的付费分类器。文件批准也不代替原工具正文或最终正文的批准。

返回正文前，用 PostgreSQL 当前时钟检查正文/post grant、每个实际使用的文件 grant、所有来源、结果和轮次的最早期限。后面的文件检查越过较早正文授权期限时，正文不返回。本人审阅及决定在审计之后再次验证这些事实和模型权限；此只读路径只查看已有规则、grant 和已通过的检测事实，不登记或执行付费检测。

Runtime 通过窄元数据投影读取来源和文件状态，不能读取原生资产块、写生产器字节或创建真人 grant。MCP 两个用途只读取四列冻结身份；运维用途只获得现有只读视图所需的三个固定 invoker 函数，不获得正文密文。本人、存储、扫描、交付的独立权限继续保留。

## 首个固定生产器的正文

`brokerrouter_fixed_mp4` 只接受服务端完整来源集合对应的正文，严格为：

```json
{"artifact_count":1,"contract":"brokerrouter-fixed-mp4-result-v1"}
```

`artifact_count` 来自原文件数量。没有原集合、首次提交任意正文、数量错误或非规范表示都拒绝；登记失败不会新增完成 receipt，已有执行回执保留。SQL 触发器同时核对固定正文 SHA 和字节数，避免绕过 Rust 检查；普通工具保持原正文契约。

固定正文、`producer_revision` 和 manifest 都是审计事实，不能单独证明生产器实际执行。该证明仍需受管生产器、独立 broker 凭据、固定镜像与真实隔离、故障恢复和组合部署验证。私有生产器候选已有实际 FFmpeg 与 SIGKILL 检查，这些证据不替代尚未完成的 PostgreSQL、原生宿主或 IdP 联调。
