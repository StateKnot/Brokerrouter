# M5.3c：护栏与策略配置

实现契约 `governance-settings-v1`，2026-09-16。Rust 事务接口、现有 OIDC BFF 和 TypeScript 管理页；不引入供应商调用、额外管理员万能令牌或新服务框架。真实部署认证仍受 LIVE-17 阻断，不把本地夹具当作生产验收。

## 权限与责任边界

复用 `serve-settings`、`br-settings+jwt` 和独立 `brokerrouter_settings` 数据库角色，环境配置见 [Key/FX 管理](m5-key-fx-management.md)。新增组织范围权限：查询需要 `governance_read`，任何写入同时需要 `governance_read` + `governance_write`；Key、FX、catalog 或 audit 权限不隐式包含治理配置权限。由现有 `console-permission-set` CLI 显式授予，不通过网页自行提权。

治理配置管理员是能改变后续安全策略的高信任角色，必须由 IdP/MFA、成员授权、审计留存和运维制度约束。配置服务不读审批/用户请求/运行结果/扫描报告，不写 turn、豁免或执行状态。它的数据库凭据只注入服务端，不能分发给网页用户。settings 签名公钥不得加入真人审批信任集合，配置签名无法用于 `/v1/approvals/.../resolve`；浏览器没有直连供应商或审批密钥。

每次操作的真人身份、组织、精确 POST 路径、body hash、有效期通过既有 BFF 定向证明绑定；同源、Secure Cookie、CSRF、会话撤销及响应后身份复查不变。新增路径仍须匹配明确白名单。服务端每次读/写均在事务中再次核对组织、用户与当前权限；写事务按 tenant → user → permission → 配置顺序持有有界锁。配置发布与运行时规则选择/审批同用 tenant 锁，不在事务中访问模型或其他外部服务。

本页不提供审批弹窗。Hermes/OpenClaw 等必须接入治理协议，才能在产生副作用前暂停、向真实用户展示风险、提交决定并恢复；普通模型 SDK 不会凭空获得弹窗或检查点恢复能力。配置人员不替终端用户作出本轮风险决定。人工批准也不会扩大 Key 模型权限、预算或工具权限，更不会重发已执行或执行结果未知的操作。

## 页面与 API

页面包含护栏配置、匹配策略、已发布策略匹配预览，以及模型/虚拟 Key/已绑定 Runtime/扫描配置 ID 查询。全部使用真实 API，无生产 mock，无新依赖。浏览器只把草稿、待确认内容与操作号放在当前内存；离开提示不是可靠取消机制。

浏览器前缀 `/bff/v1/settings`，服务前缀 `/settings/v1`，均为 POST JSON：

| 后缀 | 正文 | 返回 |
| --- | --- | --- |
| `/guardrails/query` | `limit` 1–20，可选 `search`、`after` ID | 当前完整规则、整数 `version`、字符串 `revision`、启停、分页、`can_write` |
| `/guardrails/history` | `id`、`limit` 1–20，可选整数 `before` | 不可变规则历史，按规则版本倒序；不推断历史启停，启停操作查审计 |
| `/policies/query` | `limit` 1–100，可选 `search`、`after` UUID | 完整策略选择器、字符串 `revision`、启停、分页 |
| `/governance/targets` | `kind` 为 `model`/`key`/`runtime`/`scan_profile`；`limit` 1–100、可选 `search`、`after` | ID、名称、生命周期提示，不含密钥前缀/摘要/凭据引用/用户映射 |
| `/policies/preview` | `key_id` UUID、`stage`、可空 `model_id`/`tool_name` | 实际已绑定 Runtime 对应的匹配摘要与规则版本，判定器数量超限提示 |
| `/apply` | `operation_id` UUID、`reason`、`change` | 不可变操作回执：对象 ID、配置版本、操作号 |

正文只接受定义字段，最多 16 KiB；规则内容页最多 20 条，避免 CLI 创建的大规则突破 BFF 的 2 MiB 响应限制。预览最多 256 条简要规则，不返回完整指令或检测词。默认 HTTP 10 秒、SQL 5 秒、锁等待 1 秒、8 并发；超时/连接中断不能推断提交未生效。页面明确二次核对后提交，不自动重试；手动重试冻结同一个操作号和正文，409 后必须重新读取。

两种新增变更：

- `guardrail_publish`：`id`（最多 100 UTF-8 字节）、`expected_revision`（首次 null）、`name`（最多 200 字节）、`stage`、完整 `rule`、`active`。首次必须停用。服务端分配 `version = 当前 version + 1`，不能由浏览器指定、覆盖或降低规则版本。现有 ID 的阶段不可通过网页改变，另建 ID；规则类型可在该阶段允许范围内变更。
- `policy_put`：`id` UUID、`expected_revision`（首次 null）、`guardrail_id`、可空的 `model_id`/`key_id`/`runtime_id`/`tool_name`、`active`。首次必须停用。更新提交完整选择器，不做隐式合并；启用前护栏及有关模型/Key/Runtime/扫描引用必须有效。工具名仅适用于工具阶段。

操作、审计 before/after、actor/reason/revision 与幂等回执同事务提交。同组织/用户/编号/内容重复请求只返回原回执，不再次发布；同号异内容返回 409。数据库 `config_revision` 触发器包含 CLI 的更新，旧表单不能覆盖运维改动。audit_read 页面显示已允许的真人/理由/操作号/版本，不开放任意审计 JSON；完整审计事实由受控审计存储归档。

引用查询只代表查询时的生命周期提示，不证明生产端点、用户模型授权或成本可用。模型/Key 必须属于同组织；Runtime 精确匹配已绑定 ID，指定 Key 时还核对二者一致。既有策略停用允许引用已失效或退役，避免无法关闭；停用不能被当作风险批准。没有删除规则版本、强制通过、允许 Agent 自批或批量导入任意脚本的接口。

## 支持的检测规则

| 类型 | 字段与边界 |
| --- | --- |
| `always` | 无其他字段；每次需要审批（除同轮已批准同版本） |
| `contains_any` | 1–64 条检测词，每项最多 256 UTF-8 字节；`case_sensitive` 显式布尔；检查文本/JSON，不读取二进制资产 |
| `model_judge` | `model`、`instructions`（最多 8000 UTF-8 字节）、固定 `input_format=text_json`、`max_input_bytes` 1–131072、`max_output_tokens` 16–512、`maximum_cny` 精确十进制字符串；启用需同组织启用模型和 chat 端点 |
| `asset_scan` | 精确已发布 `profile_id` UUID，仅用于服务器的 `media_output`；启用需活跃扫描配置；其策略必须指定扫描配置对应的唯一模型 ID |

网页检测词每行一项且不重复；规则统一调用服务端既有校验，不接受脚本、正则执行或任意 URL。整个 mutation 超过 16 KiB 时拒绝，不截断原规则；历史超大 CLI 配置的完整修改需走受控运维发布。停用可通过发布经过明确核对的更小停用规则完成，不会修改历史版本。

`artifact` 只检查智能体产物描述，不支持 text_json 模型判定冒充二进制检查。`media_output` 仅允许 `asset_scan` 或 `always`，媒体交付还必须有匹配的 `asset_scan`，技术扫描失败/未完成不能靠审批越过。文本语义判定实际运行时可能产生人民币费用，沿用已实现的预算、账本、防递归和受理不确定协议；保存配置/查询/预览本身不产生模型费用。本包不调整价格、汇率或历史费用。

## 版本与本轮审批语义

1. 护栏实例由 ID 标识，规则版本不可变。名称/规则/启停通过新版本发布，数据库拒绝降低当前版本，以及同版本的启停切换；延迟外键保证提交时当前指针指向真实不可变版本。停用后启用必须再发布，不会复活停用前的旧版本豁免。
2. 运行时豁免仍绑定 tenant + turn + guardrail ID + version + 有效期，只覆盖用户明确选择的护栏，不跨 turn、不变成永久白名单。发布新版本后旧豁免保留作为审计事实，但不匹配新版本。
3. 待审批动作保存实际被选中的规则快照。批准前再次读取当前选中集合；集合/规则版本变化返回 `policy_changed`，由 Runtime 重新检查后展示最新风险。管理操作本身不批准旧申请，不自动继续执行任务。
4. 策略引用逻辑护栏 ID，始终跟随该 ID 的当前发布版本，而非锁定某次规则内容；发布规则会影响所有引用它的策略，启用策略前须核对当前规则与阶段。策略选择器并非审批版本：同条策略内 AND、多条策略 OR、同护栏去重。若修改选择器后某动作仍选中完全相同的护栏版本，原申请或同轮豁免仍然有效；不能声称“任意策略编辑必然全部重审”。移除又恢复同一匹配集合也遵守此语义。需要强制重新审批时发布护栏新版本，而不是反复切换策略。
5. 在执行前完成的策略变更会影响后续重新检查；已经完成 claim/产生外部副作用的动作不会被回溯取消，未知执行结果仍须核对。输出释放与媒体批准继续执行各自的证据、过期、Key 权限及技术安全检查。

预览复用运行时选中逻辑，要求真实有效且已绑定的 Runtime Key，支持指定模型/工具/阶段。它不接收用户内容、不执行检测、不查询本轮豁免、不证明工具或模型已授权；9 个以上模型判定护栏会提示运行时配置超限。治理协议最多接受 256 个匹配护栏，超过时明确失败，不截断后运行。新编辑未保存前不会参与预览。

## 部署与验收

1. 先冻结入口/排空在途工作，核对备份与恢复证据，统计 guardrail/policy/版本规模，并检查所有当前 `(tenant,id,version)` 均存在对应版本。不要修补或删除不一致审批/账本事实来让迁移通过。
2. 迁移账号应用 `0015`；DBA 再应用更新后的 `deploy/permissions.sql`。新增只读参考列和配置表权限，不能附加 governance_control、runtime、scanner 或 operator 成员角色。保持 settings 仅连 DB、BFF 仅定向代理的网络限制。
3. 同批部署 schema 对应的 API、BFF、静态 UI 与 workers；所有服务的精确 schema readiness 必须通过。旧二进制在新 schema 上不就绪，不混跑或绕过检查。既有手工 `UPDATE guardrails SET active=...` 操作须改为新版本事务发布，禁止删除单调版本触发器来兼容旧脚本。
4. 以独立测试租户授予最小 read/write，走真实 IdP/MFA→浏览器→BFF→settings；验证跨组织拒绝、CLI 与网页编辑竞争、响应丢失同号恢复、撤权/轮换、发布新版本后旧审批拒绝、同版本同 turn 豁免保持、扫描退役后可停用。该配置验收不需要付费模型 Key。
5. 监控 409、权限/证明拒绝、5xx、锁等待、规则查询体积及审计/幂等表增长；用生产等价规模验证吞吐、容量与保留策略。幂等事实不能随意清理后允许旧操作再次发生。
6. 优先保留事实向前修复。回滚须冻结服务，评估是否已有新配置/审批/计费事实，使用与恢复点匹配的数据库和二进制，并完成在途/外部执行对账；不能仅降级 UI 或恢复旧库从而丢掉已发生费用/审批。

本地 PostgreSQL/HTTP/真实 DB 角色/故障注入、浏览器合约与可访问表单检查的结果记录在 [里程碑](milestones.md)。本包使用 ui-styling 的原生语义表单、键盘焦点和窄屏/200% 字体检查，无重绘视觉体系。真实 IdP、跨副本、SLO、备份恢复、人工读屏及生产 Runtime 整链路在 LIVE-17 验收；护栏监控、任务追踪/经验/评测页面、审批 BFF/隔离预览、Runtime 原生适配和专用多模态审核仍是后续开发。
